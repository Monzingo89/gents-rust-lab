# Local device fitting and runtime boundaries

`runtime_fit.rs` separates backend argument policy from model lifecycle, tool authorization and task acceptance. The old fixed request for 999 GPU layers is replaced by capability-detected automatic fitting. The owned llama.cpp executable must actually advertise `--fit`, `--fit-target`, `--fit-ctx` and the `auto` layer value. Compatible backends receive automatic layers with a 4096 MiB target margin. Older compatible executables use zero requested GPU layers without receiving unsupported fit options. Existing reduced-offload and zero-layer recovery remain available.

This follows the primary [llama.cpp server options](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md) and [argument parser](https://github.com/ggml-org/llama.cpp/blob/master/common/arg.cpp). Fitting is an estimate made by the installed backend against its detected devices, not a guarantee against unrelated memory pressure. It does not choose or download another model, certify a model's competence, or admit a tool. The same policy can use the local backend's supported accelerators without identifying a chip generation in application code; complete Windows/Linux deployment and isolation remain separately unverified.

The configured single-slot context is explicit in both context and minimum-fit arguments. After startup, an authenticated loopback `/props` request checks the actual slot count and context size. Missing fields, multiple slots or a changed budget prevent inference. Launch-policy requests and observed context are retained separately in local execution receipts; requested layer values are not reported as measured physical offload. Older receipts remain readable with absent optional fields. The backend never receives a model URL or download flag from this adapter.

## Minimal subprocess environment

`runtime_environment.rs` supplies a small allowlist of platform essentials and device-selection settings. llama.cpp capability inspection, llama.cpp inference, MLX inference and the local trainer clear inherited environment first. Company/provider keys, HOME, Hugging Face credentials, proxy routing, inherited llama argument overrides and PYTHONPATH are excluded. Offline flags are supplied explicitly; Python workers disable user-site imports. The owned llama.cpp server gets only its separately generated local authentication key. This reduces environment exposure; it is not filesystem confinement or a proof that dependencies have no vulnerabilities. MLX and real training have not been exercised after this change; their manifest and environment unit checks are distinct from successful fine-tuning.
