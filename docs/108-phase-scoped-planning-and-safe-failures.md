Its final error retained no dispatch or usage evidence, and structural errors from discovery kept the fallback model selected for a different prepared-graph contract. The original two failed trials, frozen fixture, source packages, profile, oracle and unknown usage remain unchanged.

## Native failure receipts

`local_generation::InferenceFailure` has a closed stage vocabulary: request send, response read, response limit, HTTP status, response JSON, final content and cancellation. Receipts retain PID, loopback port, request-attempt and observation timestamps, status when observed, received-byte count, generation allowance and numeric usage when supplied by a successful JSON response. They do not retain prompts, generated text, private reasoning, arbitrary error strings, URLs, credentials or HTTP error bodies. Request attempt is explicitly distinct from proof that the backend executed generation; unreported usage remains unknown. These error receipts never become successful execution or acceptance receipts.

The transport now enforces the existing 2 MiB limit while reading chunks rather than after accumulating an unbounded response. HTTP error bodies are discarded for both reasoning and ordinary local models. Backend load/tokenizer errors still use the existing conservative unknown diagnostic unless a typed prompt-budget receipt applies. No historical error was reconstructed.

## Owner adoption boundary

The existing authenticated planning transaction writes one `ceo_owned_selection_adopted` audit when the owner copies the exact pending model draft into source preparation. It contains the adoption revision and proposal/data/catalog digests, with no data values or source text. Only that native event resets structural-failure counting, starting at the adoption revision. Ordinary questions, protocol labels, model claims, elapsed time, cutoffs, transport errors and new messages cannot reset it. Within each phase, the exact frozen owner policy and completed non-cutoff structural-failure threshold still govern candidate selection. Ambiguous boundaries fail closed. Cache partitioning by policy/candidate/weight and all execution gates remain unchanged.

New selection proofs include `phase_scope`. The independent workflow verifier derives the boundary from native read-only audit, matches it to frozen owner-adoption metadata, checks the preceding completed review, and independently folds failures before and after adoption. Historical proofs without the new field retain their original session-wide counting; old evidence cannot invent a reset. Native custody, source/interface pins, literal inputs, typed graph validation and owner approval remain necessary.

## Owner-data grammar

For bounded complete enumerations, each data-key decoder branch lists only existing JSON pointers for that key. Root, arrays, nulls, empty keys and RFC 6901 escaping are covered. The enumeration includes every projection allowed by the existing depth, length and control-character limits. If more than 256 projections or 8192 schema bytes are needed, the whole data-argument language falls back to the original generic syntax. This avoids silently removing valid choices. No answer, function choice, invocation ID, actor, graph or source body is introduced.
