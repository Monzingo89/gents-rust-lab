# Owner-enabled company research

Public-web and repository research is enabled across the six configured local
office roles. The live office has reloaded the research assignments and global
research procedure. Its existing LEGO preview question, step and pending-effect
state stayed unchanged.

`config/company-research.json` controls defaults for newly approved tasks started
through `scripts/local-showcase-task.py`. Before intake, the owner-side runner
compiles research access for every configured actor and records the profile hash,
actual grant, frozen task and native policy installation. The native saved policy
was independently read back and matched all six actor grants at revision 1.

The defaults include public search/page reads, allowlisted repository reads,
installed skill reads, and private local memory search/append. Only the assigned
primary actor receives the task's additional tools. Other actors do not inherit
its shell, file-writing or finish capabilities. Memory sender access remains
explicit; these defaults do not share private notes between unrelated actors.

The local office already exposes the research catalog. This change adds an
explicit research expectation and removes the campaign's research-grant gap.
It does not rewrite old approved intakes or policies, broaden frozen CEO stage
contracts, or turn inference-only authoring/judging phases into tool executors.
A new research task is the appropriate boundary when an old task excludes it.

Research notes should retain primary URLs/source hashes, observation dates,
uncertainty and failed experiments. A model's note is a candidate finding;
independent evidence is still required for source publication or model promotion.
This is research and local note retention, not weight training. Public web access
uses the existing public-network guard; repository reads keep their confinement
and secret exclusions. Inference remains local-only.

## Owner controls

Set `enabled` to `false` in `config/company-research.json` to stop adding research
grants to future campaign jobs. Existing policies retain their current revision;
change or revoke them through the ordinary owner policy API when needed. This
file cannot add execution, delegation, download or external-write capabilities.
The existing task/admin/phase checks still apply to each proposed tool action.
