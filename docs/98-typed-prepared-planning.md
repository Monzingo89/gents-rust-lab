# Typed prepared-input planning

The mixed-component qualification retained two failed coder drafts that added table aggregations merely to copy existing library outputs. Their fixed roots plus unnecessary transforms exceeded the eight-source limit. A separate planning adapter now removes transformations only when their native input types make them unreachable from the current prepared roots. The execution language, source arguments, owner approval and native acceptance gates remain unchanged.

`crates/harness/src/prepared_planning.rs` applies a conservative feasibility check. Every source must be a host-prepared `owned_rust_call` input with matching component/source/API/function metadata. The inspected function's top-level output must exclude arrays. The installed native tool must retain its opaque `/output` projection boundary and expose no other array-valued projection. Every installed graph-eligible transform must require at least one array input. Under those conditions no first transformation can consume an available root; therefore no chain of transformations can start.

Unknown shapes, array-valued outputs, mismatched identities, mixed input classes, implementation mode, a new array projection, changed opaque output boundary or a future non-array consumer retain the full existing planning language. The adapter does not assume that nested arrays inside an Option/Result object are directly projectable: current native projection validation cannot descend through the opaque `/output` schema. A future native projection change causes conservative fallback rather than silently retaining this restriction.

For the proven case, `typed_prepared_roots_v1` uses the existing `native_graph_v2` representation. The decoder requires an empty derived-source array and limits artifact source references to the existing fixed input IDs. It leaves input owners, staffed actors, requested paths, result projections, encodings, writers and completion criteria to the CEO. The host still materializes roots from explicit CEO owner choices and derives minimum draft capabilities for review. Runtime validation independently rejects unreachable transforms even if a model bypasses the decoder. The prompt catalog retains the complete installed root-tool descriptor while omitting the unreachable transform descriptors; installed tools and grants are not changed.

A shorter instruction describes this same language without join/aggregation mechanics that cannot apply. It asks for missing capabilities when the requested computation is unavailable; it does not substitute another task. Initial clarification, immutable inputs, role separation, current native policy, approved source staging, exact native receipts, result readbacks and independent local QA remain. No source implementation, task answer, output mapping or permission is created by this adapter.

Planning checkpoints and canonical completion audit record the selected protocol metadata. The private journal returns the same field, and the independent workflow verifier compares saved attempts against canonical audit, normalizing absent historical protocol metadata to null. Historical reports are not rewritten. This is a host planning/prompt adapter, not an MCP version change, new actor tool or model training.

Focused tests exercise type-based pruning, conservative fallback for unknown/array/future-consumer cases, decoder bounds and runtime rejection. Contract compilation tests use different model-selected source actors and preserve their selected writer, path and exact arguments through the unchanged native graph compiler. Full regression checks and an unchanged mixed-fixture retest are required before treating this build as task-qualified. Logs use `data/mcp-basement-verification/typed-prepared-*`.


The follow-up decoder also describes native relative workspace paths separately from result pointers. `planning_paths.rs` supplies a reusable schema hint: absolute paths, traversal components, hidden components and control characters are excluded; native descriptor-relative I/O and UTF-8 byte limits remain authoritative. A character-based grammar deliberately preserves native-valid Unicode names rather than duplicating byte-level authority in the model decoder. Tests execute the expression with the installed Node runtime and compare native-valid paths, including Unicode boundaries. This does not choose an artifact name or rewrite a rejected path.

The first sealed experimental build (`1a9e4b0054e19002c05ca061d71de3ffd41415470231f0b37ad47bf12cb26882`) eliminated unnecessary transforms but repeatedly confused `/output` with a destination directory. Native validation rejected those absolute paths before admission. The fallback also produced generation cutoffs. These are observed regressions, not evidence of improved efficiency. Its immutable attempt remains retained separately from the later path-grammar build; no issued prompt, native authority or acceptance oracle is replaced in flight.
