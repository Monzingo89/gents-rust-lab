# Portable memory observations and a native SQLite security update

`mcp/src/host_memory.rs` separates OS observation (`MemoryProbe`) from snapshot bounds and admission policy. The owned adapter uses exactly pinned MIT `sysinfo` 0.40.1 with default features disabled and only `system` enabled. Its [memory API](https://docs.rs/sysinfo/latest/sysinfo/struct.System.html#method.refresh_memory_specifics) refreshes RAM; on Linux the adapter queries only the current process with command/environment/user/task refresh disabled, then uses that process's cgroup limits. The library's system-wide root-cgroup method is deliberately not used. The pinned crate source includes v1/v2 and ancestor-limit handling. This is an offline library, not a hosted tool or inference service.

Snapshot fields distinguish host RAM, process bounds and available memory. Effective values take the smaller observed limits; missing Linux process bounds remain unknown and deny optional parallel admission. Other platforms explicitly label process limits as unobserved. Available parallelism comes from Rust's OS-aware standard API, not an assumed chip core count. GPU memory remains null; host RAM is never added to a guessed GPU budget. All values are observations/estimates, not proof that a model will fit or that another computer has been tested.

`runtime_pool.rs` uses this adapter in place of the Mac-only `/usr/sbin/sysctl` command. Optional two-small-model startup admission retains the conservative total-memory reserve and now also checks observed availability with a 4 GiB margin. Serial inference remains the default. Actual GPU fitting is still the separate backend capability adapter; this change does not select, download, train or qualify a model. Linux/Windows execution and Windows job limits require further real-device verification. Capacity can change after a snapshot.

The new read-only, nondeterministic `host_resources` MCP function publishes these observations only under a current actor grant. It shares the registry, contracts, receipts and both transports. Its catalog documents source, fields, unknown limits and absence of fit/qualification authority. It exposes no hostname, account, environment, process list or command line. Tests verify denial before grants, planner/worker calls, argument rejection, epoch/revocation denial and safe catalog metadata.

The actual Mac probe observed 38,654,705,664 bytes of physical RAM and 29,502,095,360 available bytes at that instant, with 14 available parallel workers and unknown GPU memory. These are runtime observations rather than hardware specifications. The sanitized receipt is `data/mcp-basement-verification/actual-host-memory-probe.log`. It does not prove available memory on a later call or another OS.

## Native SQLite advisory

A fresh Rust dependency audit found [RUSTSEC-2026-0459](https://rustsec.org/advisories/RUSTSEC-2026-0459.html) in the pre-existing bundled `libsqlite3-sys` 0.38.2. The advisory concerns memory disclosure when opening a crafted database/WAL pair with mismatched page sizes. The harness and MCP crate now pin `rusqlite` 0.41.1, resolving `libsqlite3-sys` 0.39.1. A real connection's `sqlite_version()` and the linked native library both report patched SQLite 3.54.1.

The retained before/after audits are `host-memory-cargo-audit.json` and `patched-sqlite-cargo-audit.json`. The latter reports zero known Rust vulnerabilities and zero warnings against RustSec commit `28d73fc95e5972af3403225a217def57dcaba3c4` (updated 2026-11-10). This is an advisory-database result, not proof that the software has no vulnerabilities. The live benchmark was not restarted to apply an unrelated dependency update; the next fresh run uses the rebuilt runtime.

**Repository Python clients now use the owned patched backend:** [the private SQLite bridge](64-owned-python-sqlite-bridge.md) replaces direct system-driver use in the scheduler, curriculum journal and campaign helpers. Its actual native runtime reports SQLite 3.54.1. There is no fallback to Python's driver. The installed system Python still links SQLite 3.53.4; this repository change does not patch other programs or the interpreter itself. Do not describe the entire stack as vulnerability-free or permit untrusted database imports through the old external runtime.

All 338 default Rust tests, strict Clippy, database/governance/restart HTTP smokes and the full repository check passed, with 19 opt-in probes excluded. Focused new fixture/profile tests also passed. No model weights were downloaded or trained, no source candidate was promoted, and provider charges remained zero.
