# Local weight-space experiments

This goal studies measurable, task-specific improvements to the installed models.
It does not promise that editing weights produces universal competence. Original
weights stay immutable; candidates stay separate and receive no new tool, memory,
or communication permissions. Provider spending is zero. Electricity, hardware
wear and operator time are real costs and are not currently priced.

## Method and boundaries

[Task arithmetic](https://arxiv.org/abs/2212.04089) constructs a task vector from
the difference between compatible fine-tuned and original parameters. It is not
a method for inventing arbitrary capable weights without training or evidence.
Different architectures, tokenizers, tensor layouts and quantization schemes are
not interchangeable. Never add floating-point deltas to packed GGUF integers.

The first supported method is local [MLX LoRA](https://github.com/ml-explore/mlx-lm/blob/main/mlx_lm/LORA.md):
a learned low-rank parameter change alongside a frozen base. This is an adapter
experiment, not evidence that task-vector merging or direct weight programming
has been implemented. Full pretraining from scratch is not an economical default
on this workstation. Longer runtime alone cannot guarantee a successful result.

## Frozen experiment protocol

1. Select a locally installed compatible model and a narrow role task. Record
   base hashes, source hashes, dataset hashes, limits and expected outputs.
2. Keep training, validation and test prompts separate. Use owned synthetic data
   initially; do not silently train on company documents, private evaluations,
   other agents' memory, or user images.
3. Measure baseline generated answers before training. Never send the expected
   final answer to inference. Store the baseline before making parameter changes.
4. Train under the existing company GPU lease, offline, with fixed iteration and
   sequence bounds. Stop at the bound and retain failures.
5. Generate answers again with the same prompts and deterministic decoding.
   Report each failure and each regression, not just an aggregate score or loss.
6. Rehash original files. Keep the adapter quarantined. Better held-out loss does
   not establish better task completion. A passing experiment does not authorize
   production promotion. Qualification needs independent prospective cases.

Once test cases have influenced a new experiment design, treat them as development
cases. Repeated optimization against the same test set is not held-out evidence.
Six synthetic cases cannot establish statistical significance or industry readiness.

## Implementation

`scripts/train_role.py` owns local training and calls the separate deterministic
scorer in `scripts/weight_task_evaluation.py`. Generated outputs have a 96-token
cap; capped/wrong answers fail the same frozen criteria. No repair model rewrites
an answer before scoring. JSON comparison rejects duplicate keys, nonfinite
values, extra Markdown and boolean/number coercion.

Each private training run retains `task-baseline.json`, `task-candidate.json`,
`task-comparison.json`, `metrics.json`, and the adapter. Existing base/adapter
hashes and company training records provide lineage. `experiment.json` records
the initial experiment's source hashes. These files are local evidence, not signed
attestations against a malicious same-user process.

The first fixed fixture is generated by `scripts/prepare_weight_experiment.py`:
20 training records, 5 validation records, 4 unseen extraction cases and 2 basic
regression controls. It does not read the previously failed company JSON tasks.

## First result, November 14, 2026

Run `63e37c7a-13bc-4a01-95d7-1dd35151e453` completed 50 actual local LoRA
updates on Gemma-4-E4B-it. It used the company runtime's shared GPU queue.
Held-out prediction loss decreased from 3.69039 to 0.75963, but generated-answer
accuracy remained **6/6 before and 6/6 after**. There were zero observed regressions
on these six cases and **no demonstrated task-capability improvement**. The
adapter remains an unpromoted candidate. The base hashes remained unchanged.

Measured training/evaluation time was 37.61 seconds and peak MLX memory was
15.264 GB. Provider fees were $0; electricity was not measured. These measurements
do not include all operator, source-development, registration or verification time.
The [source-derived result](evidence/weight-experiment-2026-11-14.json) records
the adapter hash, base fingerprint and independently recomputed comparison.

## Second result: event folding

Run `596311eb-f6f9-45f3-9968-5b30e27b4ec1` used a newly frozen synthetic
event-folding benchmark: keep the last event per ID, remove deleted records,
sum quantities by SKU, retain zero totals, and treat instruction-like notes as
data. Twenty training cases, five validation cases and twelve test cases were
fixed before inference. Two test cases are elementary regression controls.
An executable oracle and independent hand-calculated tests define correctness.

The baseline passed **1/12**; after 100 local LoRA steps the candidate passed
**2/12**, with no observed pass-to-fail regressions. Reconciliation itself went
from **0/10 to 1/10**. Arithmetic stayed correct; the JSON-only formatting control
still failed. Loss decreased from 2.90808 to 0.69350. This is a narrow one-case
gain, not reliable reconciliation competence. The adapter was **not promoted**.
Time was 65.28 seconds, peak MLX memory 15.634 GB, provider fees $0.

[Verified result](evidence/weight-event-fold-2026-11-14.json).
Recheck without inference:

```sh
python3 scripts/verify_weight_experiment.py \
  data/companies/we-need-gents-lc/training/runs/596311eb-f6f9-45f3-9968-5b30e27b4ec1
```

The verifier rehashes source snapshots, base weights, adapter and all dataset
splits, binds each recorded prompt and expected answer to the frozen test data,
and recomputes individual scores. It does not establish tamper-proof execution
provenance against a privileged local user.

`scripts/model_improvement_inventory.py` additionally inventories nested media
weights without loading them. It reports physical artifacts and configured role
claims, rejects linked artifacts, and explicitly does not grant model admission.
The local report is `data/model-registry/improvement-inventory.json`.

Next: broaden training examples beyond the repeated event structure, compare a
targeted candidate on fresh prospective cases, and separately qualify persisted
adapter reload behavior and unrelated task retention. Do not repeatedly optimize
against the now-observed twelve cases and call them unseen evaluation data.

## Third result: varied events and adapter reload

Run `a5608814-dd9d-49cd-888f-a1eb2ea526f7` froze 160 training, 20 validation,
and 24 prospective test cases before inference. Event counts, order, quantities,
IDs, SKU changes and deletion patterns varied. An independent reverse traversal
checked every synthetic oracle. Four tests cover elementary arithmetic and JSON
formatting. This run started from the unchanged base, not the previous adapter.

After 400 local LoRA steps, accuracy fell from **10/24 to 9/24**, with **one
regression and no new passes**. Prediction loss nevertheless decreased from
2.44192 to 0.43909. The candidate is **rejected for observed task regression**;
the private `experiment-decision.json` binds that decision to its adapter hash.
It was not promoted. This is evidence that reduced prediction loss alone is an
unsuitable promotion criterion.

The runner released the trained in-memory model, reloaded the base and saved
adapter, then regenerated all 24 answers. Every output matched exactly, including
the failures. The reload happened in the same worker process after releasing the
model and clearing MLX cache; it was not a separate OS-process restart test.
The evidence verifier now rechecks reload outputs and their frozen oracles.

Measured run time was 207.37 seconds; peak MLX memory 15.711 GB. Provider fees
were $0; electricity remains unmeasured. Original base hashes remained unchanged.
[Verified result](evidence/weight-diverse-events-2026-11-14.json).

Sixteen focused tests cover datasets, independent oracle calculations, scoring,
changed weight rejection, altered oracle rejection, and reload mismatches.
The live promotion API now enforces task-evidence admission before separate
operator review attestations. No candidate from these experiments is approved
for live company use.

Next experiments must use fresh holdouts and a reasoned change in training
method or task representation. Repeating the same small final-layer update for
more iterations has not established reliable reconciliation skill.

## Live promotion rejection gate

`crates/harness/src/company_training_gate.rs` is separate from training and from
the company's database mutation logic. Promotion requires baseline, candidate
and reloaded-output records with matching unique task identities and oracles.
The gate recomputes pass counts from individual host-recorded pass flags, rejects
any pass-to-fail case, requires a positive gain, and checks exact reload output
agreement. Aggregate claims cannot override individual recorded regressions.
Missing legacy evaluation or reload evidence fails closed. Existing owner review,
privacy/license attestations and base/adapter byte-hash checks remain required.

This gate consumes trusted host evaluation records. It does not independently
execute the Python scorer or bind evaluation records cryptographically to an
unforgeable inference receipt. The separate verifier recomputes output scores and
checks dataset hashes; malicious same-user report replacement is not addressed.

After rebuilding and restarting the idle local office, an HTTP request against
the actual regressing trial returned **400: observed task regression prohibits
promotion**. Its database state remained `candidate`, never `active`. The probe
used an empty owner review so it could not authorize promotion even if the new
gate were absent. [Live rejection evidence](evidence/weight-promotion-gate-2026-11-14.json).
Fourteen company tests, the development build and strict Clippy checks passed.

## Fourth result: four-layer adapter

Run `9f248652-6009-42d9-b08d-aa547a1d69d4` tested a bounded four-layer,
rank-eight LoRA profile at the same learning rate, using 400 steps from the
unchanged base. The dataset contained 160 training and 20 validation cases,
20 new prospective event tests and four retained elementary regression controls.
New event prompts were checked against the prior trial's test prompts before
registration. This is a new test set; its raw score is not directly comparable
to the third trial's score.

Accuracy increased from **3/24 to 4/24**, with one new event-case pass and no
pass-to-fail regressions. Loss decreased from 2.79795 to 0.22537. Every saved
adapter reload output matched the in-memory output. The adapter remains
**unpromoted**: a one-case gain with twenty failures does not establish useful
reconciliation competence or statistical significance.

Runtime was 224.30 seconds, peak MLX memory 15.818 GB, and provider fees $0.
Original weights were rehashed unchanged. [Verified result](evidence/weight-four-layer-2026-11-14.json).

`scripts/weight_training_profiles.py` defines two bounded profiles, preserving
the original conservative default. Unknown profiles are rejected before loading
weights, and parent adapters with incompatible profiles cannot be resumed.
Training progress now distinguishes candidate evaluation from saved-adapter
reload evaluation. Seventeen focused Python tests passed.

These results do not support continuing to increase iterations blindly. A useful
next experiment is learning the company's tool-selection contract for language,
audio and image requests, with independently checked tool identifiers and denied
capability cases. Better routing would still not prove better media generation.

## Fifth result: output-intent contract

Run `99c10ee3-3994-4d62-9279-2eb006eaaf85` used the existing output-intent
judge instruction, plus an explicit canonical modality-order requirement.
It trained an experimental four-layer rank-eight adapter for 200 steps on
80 owned synthetic examples, with 16 validation and 24 frozen test cases.
The experiment stayed in the existing isolated training role; it did not replace
the production CEO or output judge. Tool permissions and execution stayed in the
host. The benchmark covers classification only, including mixed outputs,
negation, quoted instructions, unavailable video and an authority-injection request.

Strict scores improved **0/24 to 11/24** with no observed strict-score regressions.
Reloaded adapter outputs matched exactly. Runtime was 118.40 seconds, peak MLX
memory 15.671 GB, provider fees $0. Original base hashes remained unchanged.
[Verified result](evidence/weight-output-intent-2026-11-14.json).

This gain is chiefly **format compliance**, not semantic improvement. The baseline
often emitted bare labels instead of JSON. A post hoc diagnostic that reads bare
newline-separated labels or schema-valid JSON finds the correct modality set in
23/24 outputs both before and after training. Valid production-intent JSON rose
from 0/24 to 15/24; four of those candidate answers failed the benchmark's
additional canonical-order requirement. The production schema itself does not
require that order. These diagnostic counts do not replace the frozen strict
scores or authorize a permissive production parser.
[Diagnostic report](evidence/weight-output-intent-diagnosis-2026-11-14.json).

Both versions misclassified writing a video script as producing video. The
adapter remains **unpromoted**, and no media-quality, permission-enforcement or
end-to-end task improvement is claimed. Nineteen focused Python tests passed.
Before further routing training, a fresh qualification suite must test broader
language/negation patterns and unrelated retention; schema-constrained decoding
should be measured as a separate system change, never labeled a weight gain.


## Completion-model compatibility preparation

The worker now has an explicit `prompt_format` adapter. `chat-v1` remains the
existing default. `completion-v1` accepts one raw user prompt and one assistant
completion, masks the prompt during training, and encodes the same raw prefix
without added special tokens during inference. Unknown formats and multi-turn
completion examples fail closed. This avoids inventing a chat template for a
base model.

A frozen, owned Phi-1 fixture contains 40 training, 8 validation and 12 test Python
function-completion examples. Its installed tokenizer passed all 60 round-trip
and prefix checks; maximum length was 39 tokens. The tokenizer has no chat template.
Two adapter tests and six existing training tests passed after this change.
**No Phi weights were loaded, trained or evaluated for task quality yet.** The
fixture uses the same simple templates across distinct function names; it cannot
establish general coding ability. Source release preparation interrupted the next
native trial; do not report that unexecuted experiment as an improvement.
