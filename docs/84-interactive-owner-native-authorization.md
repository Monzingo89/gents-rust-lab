# Interactive owner authorization

The CEO execution review now offers the same owner choice as the qualification CLI. The default reviews each proposed operation with the local model. For eligible native data-to-file plans, the owner can instead select **Execute exact approved native steps** before preparing the frozen review. This removes repeated model authorization for those exact worker operations; native permissions, source identity, contract enforcement and independent final QA still apply.

`web/assets/owner-authorization.js` is the shared pure policy-draft adapter. The CLI reexports it. It neither calls a model nor installs authority. It preserves task facts, criteria, actors, grants and communication edges, adding the existing worker-only native contract constraint to an unissued draft. Empty native bindings and source-authoring/required-Rust-check plans are ineligible. The native MCP transaction remains the enforcement boundary, for both stdio and authenticated local SSE. A browser selection alone cannot authorize a tool.

The UI review binds consent to the API origin, company, planning session, canonical revision, exact artifact-binding editor contents and authorization mode. Changing any of those clears the review and consent. Async intake responses are checked against that context before displaying an approvable review. Loading or starting another conversation restores the default mode. Issued jobs cannot change modes through this adapter.
