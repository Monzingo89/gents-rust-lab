# Next-action authorization context

The fresh weighted-slot v2 retest exposed an authorization-context error. At event 59 of run `21e8aeff-79a4-41fd-93e0-7b0b4f28a588`, the next request was `files` with `op=read`, but the local admin denied it with an explanation about repeating a write. The packet also contained the earlier successful write's complete 2,384-byte source body. That observation motivates a narrower context view; it does not prove that historical source text alone caused the model's error. The original denial, recovery and subsequent independently authorized actions remain in the run history.

`authorization_context.rs` now owns this view separately from the permission system, Rust parser and completion reviewer. The packet begins with `action_under_review`, derived from the exact request's action, operation, path and argument digest. The exact request remains intact, including a proposed write's full content and precondition. An instruction explicitly distinguishes `op=read` from `op=write` and historical operations from the next proposed action.

Only an earlier successful native worker `files:write` with internally consistent actor, phase, epoch, argument digest, result digest, path, byte count and content digest is eligible for body omission. Its view retains the receipt, original operation/path/precondition, content digest/size and original-record digest. The view explicitly states that it is not replayable, does not establish present file state or authority, and does not satisfy readback/tests. The full record stays in the journal/checkpoint. Failed, uncertain, unreceipted and inconsistent rows are left intact. A body stays intact when the metadata would make the packet larger. The digest checks establish envelope linkage, not an authenticated signature or a new canonical observation.

The existing current-policy/native gates and independent admin decision still apply. This change never converts a deny to allow. It supplies no task implementation and does not modify the running retest's executable, fixtures, source, grants or checkpoints. Its effectiveness on later local-model execution must be measured separately; unit/HTTP fixtures are not evidence that a real model always interprets requests correctly.

An `authorization_context` event records the focused action, number of omitted historical bodies and prepared packet size/digest. It does not copy source bodies or assert a verdict, tool execution or authority. Its digest is explicitly for the packet before `model_call` wraps/compacts it, not a claim that it equals the final native dispatched-input digest. Normal call provenance remains separate.

Verification covers exact request preservation for both reads and writes, preserved deny verdicts and preconditions, retention of failed/uncertain/inconsistent evidence, size-reducing/idempotent views, unchanged canonical policy/receipt counts after preparing a view, and a real native write followed by a separately executed read. The HTTP autonomy smoke checks that public metadata binds to the exact journaled write arguments without copying its body. These checks use explicitly simulated model judgments and real host/MCP operations.

The complete repository check passed with 362 default Rust tests, 20 excluded opt-in probes, strict Clippy, HTTP/Python/Node checks and the UI build. The idle office was updated only after this check. Evidence logs and receipts use the `authorization-focus-` prefix under `data/mcp-basement-verification/`. The fresh retest independently passed on its original build; its result therefore is not a real-model validation of this later view.

At implementation time, public intake accepts at most eight criteria, while the keyed review protocol accepts up to 64. No batching or intake-limit change was introduced. The broader objective still includes larger tasks, additional modalities, governed hardware/model acquisition/training and field-specific assurance. Neither a synthetic scheduling pass nor these context checks establish banking/healthtech compliance, vulnerability freedom or universal task competence.
