# CEO-proposed native checks and immutable inputs

The local CEO can now propose native source-to-artifact checks during planning.
The company still requires operator review and approval of a frozen job digest.
A proposal cannot execute a tool, install a policy or promote source code.

## Representation and authority

`native_contracts` contains up to eight read-only sources and sixteen artifacts.
A source has a unique id and assigned actor. Each artifact references a source
id and selects its writer, workspace path, JSON pointer and encoding. Several
outputs can reuse one source. The pure `ceo_contracts` compiler expands these
references into the existing MCP artifact binding contract, validates current
native input schemas and checks the ordered team's tool/actor boundaries. No
arithmetic calculation or task answer is generated by this compilation.

Sources use registered read-only functions or files read/list operations. File
writes cannot be disguised as planning sources. Unknown references, duplicate
paths, unused sources, missing writer capabilities and backward actor edges are
rejected. Arithmetic projections additionally check native field names, row
positions and output types. Other native projections are checked against actual
results at execution; they are not claimed to have static result schemas.

The accepted proposal, source inputs, expanded bindings and binding origin are
frozen into the owner-reviewed intake. Explicit operator binding edits remain
possible and are labeled separately. They still pass native path, input, actor
and policy checks. A model cannot use this edit path to grant itself tools.

## Preserving exact user inputs

The real model trials exposed an important failure: a CEO draft described the
right signed inputs in prose but emitted an empty values array in its source
arguments. The independent experiment rejected it before approval. Another
attempt selected the wrong encoding for an integer output. These failures are
retained; neither is counted as successful tool execution.

For exact data, the planning API accepts optional `source_inputs` attachments:

```json
{
  "message": "Calculate this balance and save the native difference to total.txt, then read it back. Use separate analyst and writer roles.",
  "expected_revision": 0,
  "source_inputs": [{
    "id": "approved-input",
    "tool": "integer_arithmetic",
    "arguments": {"calculations": [{"id":"balance","values":[73,-29,18],"subtract":7}]}
  }]
}
```

Attachments are validated read-only inputs, not tool grants. Their ids and
contents are immutable within the conversation. Repeating identical attachments
is allowed; changing data under an existing id is rejected without advancing the
conversation. Start a new conversation for changed input data. Attachments are
bounded, owner-scoped and checked by the existing persistence/privacy rules.

When attachments exist, the local model's decoder schema permits only an input
reference, not copied tool arguments:

```json
{
  "native_contracts": {
    "sources": [{"id":"balance-source","actor":"Engineer Gent","input":"approved-input"}],
    "artifacts": [{"path":"total.txt","source":"balance-source","writer":"PM Gent","pointer":"/calculations/0/difference","encoding":"integer_text"}]
  }
}
```

The host resolves that reference from retained user data. The model chooses the
actor and output check, while the original signed values remain exact. Inputs
and source ids are distinct so the CEO can reuse inputs without copying data.
Free-text tasks without attachments still support literal source proposals;
those literals require careful operator review. Their schema validity alone
does not prove faithful extraction from natural language.

## Prose, evidence and debugging

A recovered draft also repeated a made-up numeric acceptance answer from an
earlier CEO message, despite correct native input references. That experimental
run was explicitly cancelled after observing the loop, and remains failed.
Planning now projects user messages and CEO clarification questions into the
next inference prompt. Prior staffing is supplied separately; old draft prose
is retained in the full transcript but is not carried forward as factual input.
Ambiguous user references to an omitted criterion require clarification.

For arithmetic contracts, a numeric-literal guard rejects prose numbers absent
from supplied user facts, source inputs or contract structure. This catches the
observed invented answer. It is a limited grounding check, not proof of semantic
truth: a wrong claim can reuse an existing number. Actual native results,
actor-scoped receipts, exact artifact checks, review and operator authority
remain separate requirements. The guard does not turn model prose into facts.

Safe validation errors are retained in planning state/audit and supplied to the
next turn as repair feedback. Rejected raw output remains a hash rather than a
payload dump. The planning read API exposes metadata for every audited attempt,
including failed validation and its measured usage when available. Missing
usage or execution provenance remains explicitly unknown. Experiment totals
include rejected planning attempts instead of counting only transcript replies.

The CEO office shows exact source inputs, compiled proposed artifact checks,
planning attempt metadata, the frozen scope and approval digest. Preparation
creates a draft; a separate explicit action approves, installs scoped policy
and starts execution. The basement catalog continues to describe implemented
functions rather than granting access.

## Verification

Focused Rust tests cover input immutability, reference substitution, decoder
constraints, projection types, actor/tool boundaries, unsupported numeric
claims, omission of prior model answer claims, frozen defaults/owner edits and
privacy of planning attempt metadata. Existing transport, audit, epoch, native
receipt and artifact tests remain authoritative for execution.

The real experiment supports `--ceo-contracts`, selecting bindings from the
actual saved CEO proposal. It independently checks the original arguments,
projection, encoding and every requested path before approving anything.
Scripted fake-user repair messages are labeled as user fixtures; they are not
presented as autonomous CEO self-repair. Old failed conversations that exhaust
the planning budget are retained; a fresh bounded conversation is required.

Run the one-artifact and harder four-artifact experiments with:

```sh
node scripts/mcp-team-check.mjs --normal-only --challenge --ceo-contracts
node scripts/mcp-team-check.mjs --normal-only --multi-artifact --ceo-contracts
```

These use the installed native local model, owned isolated listeners, no
provider credentials, no downloads and no paid inference. CEO/admin/QA calls
still consume local model tokens. The representation and host checks improve
task execution; no weight training or general arbitrary-task capability is
claimed. The overall company goal remains active.
