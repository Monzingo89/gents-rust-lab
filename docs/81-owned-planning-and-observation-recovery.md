`owned_work.rs` separates local work ownership from the HTTP observer. The authenticated planning route starts host-owned work, then awaits its result; disconnecting that waiter does not abort the task. A real private HTTP regression closes the TCP observer, verifies the handler was dropped before releasing its operation, and independently reads the committed SQLite result. This tests lifecycle behavior with a controlled operation, not model competence. Process shutdown still interrupts local work. Owner abandonment invalidates a pending checkpoint and does not itself attest backend termination; inspect native activity before recovery.

`mcp-planning-observer.mjs` sends a planning POST once. A lost transport response leads to read-only polling of the same session and exact next revision. Explicit HTTP errors are not retried as model calls. Missing authority, changed identities/revisions and unknown states retain uncertainty. The observer never infers terminal status from elapsed time. Client observation and server work ownership are separate modules and separately tested.

It verifies the original fixture, exact model profile, pinned inputs, owner constraints and conversation identity before lease mutation. A child `--preflight-planning` exercises the actual runner's read-only path before reserving work.
