# Native acceptance preflight

The settlement v1 fixture exposed a gap in benchmark preparation: ordinary Rust type-checking does not prove that owner-authored tests meet the native verifier's intentionally narrower dialect. The native policy rejected its vector-allocation macros before candidate tests could execute. The host fixture error and explicit maintenance cancellation remain in the original attempt history; neither a candidate failure nor successful acceptance is inferred from that interrupted trial.

`rust_verification::acceptance_policy_observation` now exposes the same parser/dialect/test-count validation already used inside actual native verification. It returns source bytes/digest, compiled parser-policy digest, admitted test count and a narrow scope statement. Rejection never echoes source-dependent identifiers or payload text. No compiler, test executable, model, tool execution, permission or promotion is invoked or established.

The private `gents-rust-acceptance-check` executable lives in the owned `mcp/` package but is absent from the agent MCP registry. It accepts only bounded stdin (1..8192 UTF-8 bytes), rejects command arguments and oversized/invalid input, emits bounded JSON and exits nonzero on rejection. It has no file-path, credential, shell, code-loading or network interface. Build it with `cargo build --workspace --locked`.

`scripts/mcp-rust-acceptance.mjs` owns the host adapter. It requires an ordinary owner-controlled local checker and non-symlink build directories, sends the frozen bytes under a five-second/16-KiB output bound with a minimal environment, and checks the source digest, source length, test count and compiled-policy digest against the current parser source. Missing/stale/malformed/rejected responses fail closed. This is preparation evidence, not running-process attestation, reproducible-build proof or a replacement for canonical acceptance.

The curriculum checks a Rust fixture before allocating its execution lease or starting local-model work. Direct coding runs check before starting their listener/planning/models; continuation checks happen before lease changes. Successful runner reports retain `frozen_acceptance_preflight` separately from actual runtime/compiler/test evidence. No agent-facing capability or policy grant was added, and actual source-bound native acceptance is still required before completion.

Verification exercises every current Rust fixture against the actual compiled parser; rejection of Rust-compilable forbidden macros, missing tests and malformed test code; declared-count mismatch; oversized/non-UTF-8/empty input; absence of source echo; and unsupported CLI arguments. Separate oracle/type checks remain because parser admission alone does not prove that a suite compiles, computes the intended oracle or covers the task contract. The corrected settlement v2 keeps the original task and acceptance difficulty.

The complete repository check passed with 363 default Rust tests, 20 excluded opt-in probes, strict Clippy, HTTP/Python/Node checks and the UI build. Evidence uses the `acceptance-preflight-` prefix under `data/mcp-basement-verification/`. No model or network request is made by these parser checks.
