# Owner-attached local task files

The CEO browser flow now accepts actual local JSON tables, rather than only declarations of paths that an operator had to populate through another program. The files are user-supplied task data. They do not install capabilities, approve work, supply evaluator answers or enter the CEO inference prompt as raw rows.

The browser reads only explicitly selected files. It preserves UTF-8 bytes without newline normalization and rejects invalid UTF-8, duplicate filenames, more than eight files, files larger than 8192 bytes and more than 32768 total bytes. The server independently enforces these limits and the existing native table import rules: unique decoded keys, flat scalar records, integer numbers and bounded field/row counts. Paths must be plain ASCII JSON filenames. The planning endpoint alone has a larger bounded HTTP body allowance; other endpoints retain their existing limit.

`source_files` in a planning request contains `{id,path,text}` uploads. Retention happens inside the same SQLite transaction as the planning turn; a rejected turn leaves no partial attachment. Exact bytes reside in the private company database. Session responses contain only `{id,path,bytes,sha256}` manifests and immutable `table_read_json` source declarations pinned by `expected_sha256`. An existing input ID cannot be changed. The browser fixes its selection after the first successful turn and displays the retained manifests; changing files requires a new conversation. CLI clients may add distinct inputs during the existing bounded conversation.

Intake copies the retained manifests from the ready session, rather than trusting a caller-supplied replacement. They become part of the frozen intake digest shown for approval. Admission checks the normal approval and exact frozen task before touching a workspace. It checks retained content against its hash, checks frozen manifests against retained manifests, and uses the existing descriptor-relative MCP adapter to stage files. Symlinks and conflicting existing bytes are rejected. Matching existing bytes are reused; a partial staging failure permits inspection and retry before any agent dispatch, without overwriting conflicting files. Complete readback checks every staged hash and byte count. The company audit records `owner_source_files_staged` with manifests and session ID, never raw file contents. Staging adds no actor permissions; each later native read still needs its approved policy and expected hash.

Frozen owner source paths are also protected after staging. Native MCP rejects agent file writes to attached source paths and frozen table-read input paths before any filesystem effect, even when the actor has file-writing permission. Artifact validation rejects output destinations that overlap those inputs. Other approved output paths continue to work. This guard uses the existing policy-fenced transaction and adds no separate inference or provider cost.
