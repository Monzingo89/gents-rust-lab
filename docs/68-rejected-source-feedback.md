# Rejected-source feedback for local recovery

The weighted-slot v2 run repeatedly proposed source containing forbidden macros. The native parser and independent admin correctly rejected those writes. Inspection found that subsequent worker prompts kept executed-tool evidence but dropped the `denied` records and their reasons. No tool result existed for these rejected writes, so recovery could repeat the same syntax error without seeing the diagnostic. The local model's internal reasoning and sole cause of failure are not inferred from this observation.

`rust_review::repair_feedback` now projects retained denials into a separate `proposal_feedback` field for worker and executive recovery. It matches the current frozen author/source pair and stage, re-runs the owned parser against the retained proposed bytes and returns the exact source hash, current parser-policy hash and bounded diagnostic. It supplies no source body or reference implementation. The independent admin's explanation remains explicitly advisory, separate from parser facts. A model claim cannot turn parser admission into a syntax failure.

The field describes unexecuted proposals, not executed tool evidence or the current workspace contents. It does not compile, write, run tests, change policy, authorize a tool, qualify an artifact or promote source. Correctness still requires authoring, actual full readback, isolated owner-frozen tests and independent final review. The original rejection and candidate text remain in their private history; this projection does not rewrite either.

Only the newest relevant denial per path is projected, up to three paths. An actual successful native write of the matching bytes retires older rejection feedback for that actor/path/stage. Failed or hash-mismatched writes cannot do so. Scoped recovery compaction retains the feedback while removing duplicate catalogs and activity indexes. The parser is not repeatedly invoked for older proposals after that path is resolved in the projection.

Unit tests cover exact actor/stage/frozen-path filtering, newest-denial selection, body omission, unexecuted labeling, parser facts versus model explanations, and retirement only by a matching successful native write. A real HTTP/restart smoke seeds one rejected proposal in a disposable fixture and verifies that the feedback reaches actual worker dispatch. Its simulated worker requests a diagnostic marker; independent admin authorization remains required, and no file/tool effect or task completion occurs. This is a runtime regression test, not proof of real-model competence.

Source-repair protection now includes the Rust proposal/recovery adapters and scoped worker-packet compactor. Evidence is retained in `data/mcp-basement-verification/rust-proposal-feedback-*.log`. Real task behavior, interventions and runtime-build fingerprints must be measured separately; passing these tests alone does not establish improved task success or eliminate hallucinations.
