# Type-directed local function selection

The local CEO can now select inspected owned functions through a decoder that uses their actual native parameter types. For each function and argument position, the host offers all compatible projections of owner-supplied data, plus the existing result-reference language. It does not choose a function, compute an answer, assign an actor or grant permission.

The pure builder lives in `crates/harness/src/selection_grammar.rs`; `owned_selection.rs` binds it into the existing question/selection-review protocol. Native selection review still checks literal marshalling, prior references and result projection types. Owner adoption, graph planning, source custody, actor/phase policy and native execution remain separate gates.

## Conservative bounds and compatibility

Projection enumeration shares the native pointer syntax and handles whole values, nested arrays/objects and escaped JSON keys. It stops at six levels and declines the optimization when projection count, encoded size, function count or supported descriptor bounds are exceeded. The caller then retains the existing generic grammar. It never silently supplies a partial menu of compatible data.

Tuple arity is expressed with equal `minItems`/`maxItems` and matching `prefixItems`. The owned local decoder rejects boolean `items:false`; omitting `items` preserves exact arity while using its supported schema subset. This omission applies to the decoder adapter, not the native ABI descriptor or runtime validation.
