# Owned patched SQLite for Python bookkeeping

The curriculum journal, scheduler and synthetic campaign helpers previously opened databases through the installed Python driver's SQLite 3.53.4. They now import `scripts/local_sqlite.py`, an intentionally small adapter to the private `gents-sqlite-bridge` Rust binary. That binary links the same pinned, bundled SQLite 3.54.1 used by the native MCP server. The operating system Python installation is unchanged. This closes the repository clients' dependency path to the older library, not every program's SQLite exposure.

Build with `cargo build --workspace --locked --offline` before starting maintenance clients. The adapter fails closed when the owned binary is missing, insecurely writable or reports an unsupported protocol/runtime. It never imports `sqlite3` or `_sqlite3`, installs another driver, or reconnects through a fallback. `scripts/run-company.sh` already builds the workspace. This binary is absent from the MCP catalog and grants no agent database authority.

One connection owns one subprocess and a bounded JSON-line channel. Database paths and parameters travel through private pipes, not command arguments. The child receives a small OS environment allowlist, excluding model/provider credentials, proxy settings and Python module paths. SQL parameters remain typed parameters. Unix-created files use mode 0600; the native open rejects leaf symlinks. Parent paths are canonicalized to support the Mac `/var` alias. This is trusted-host bookkeeping, not a descriptor-confined arbitrary database import tool. Windows ACL enforcement and real Linux/Windows execution still need independent verification.

The supported interface covers the repository's positional scalar/blob parameters, cursor iteration and row factories, ordinary deferred DML transactions, explicit transactions, read-only file URIs and bulk DML. It deliberately does not claim full Python DB-API compatibility. Extension loading is disabled. Unsupported isolation and network URI modes fail closed. Queries have SQL, parameter, cell, row, response and execution bounds. Errors omit SQL, parameters and database payloads.

Transport failure after an effect is an uncertain outcome. The adapter closes the connection, never reconnects and never replays a request. An actual injected lost COMMIT acknowledgement test confirms that a fresh observer sees exactly one committed write. Process-death tests confirm rollback of uncommitted work. These properties do not make filesystem effects and audit writes one distributed transaction.

Nine actual bridge integration tests passed, including constraints, locking, two-client unique lease admission, read-only writes, leaf symlinks, malformed SQL redaction, extension denial, missing-binary failure, and a fresh Python process proving the system driver was not imported. Scheduler, curriculum, enterprise helper and source protection tests passed. Strict workspace Clippy and the full repository check passed, including 338 default Rust tests, HTTP governance/restart smokes, Python/Node checks and the UI build; 19 opt-in Rust probes remain excluded.

The saved cents retest and graph qualification were independently revalidated against canonical native authority using this patched backend, without rerunning those tasks or admitting new curriculum attempts. Receipts: `data/mcp-basement-verification/patched-python-canonical-reverification.json`. Broader check output: `patched-python-complete-check.log`; bridge tests: `local-sqlite-tests.log` in the same directory. Existing before/after Rust dependency audit receipts remain in that directory; their zero-known-advisory result is not a vulnerability-free certification.

The active weighted-slot task kept its original run UUID, frozen tests, grants and model profile during this change. No candidate implementation was supplied by the frontier model, no model weights were downloaded or trained, no source was promoted, and task provider charges remained zero. Local inference, machine time and frontier development still consume resources.
