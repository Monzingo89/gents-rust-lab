`local_generation.rs` owns generation limits separately from device fitting, backend lifecycle, agent governance and task acceptance. The trusted local role configuration may set `local_reasoning_tokens` to an integer from 0 through 4096. Absent or zero preserves the default off behavior. Other providers, including MLX and paid providers, reject the field. Agent `model_select` proposals cannot enable it. The evaluation profile records the requested setting and hashes the complete configuration.

An enabled call requires the installed executable to advertise bounded reasoning, a separated output format, disabled reasoning preservation and disabled backend logging. Unsupported backends fail before loading. The launch uses `--reasoning on`, a finite `--reasoning-budget`, `--reasoning-format deepseek`, `--no-reasoning-preserve` and `--log-disable`. Each generation request and tokenizer preflight use matching template settings. Changing the reasoning budget stops the owned backend before reuse; tenant/run/policy cache isolation remains unchanged.

The final output allowance and reasoning budget sum to a bounded total generation cap. Both, plus the existing 256-token margin, are reserved before dispatch. The final allowance is a reservation, not a guarantee that an arbitrary template will finish its answer. Frozen task requirements are never truncated to fit. Required input that still exceeds capacity fails clearly; only existing optional context may be compacted.

Only `message.content` becomes the public reply. Empty or visibly unseparated thinking content is rejected in enabled mode. Private `reasoning_content` is discarded; receipts retain its presence as a boolean, the requested budgets and the backend's actual usage/context. Enabled HTTP failures discard the response body. Backend logging is disabled for enabled inference. This reduces trace retention in this adapter; it is not a proof against a malicious model or backend. Missing reasoning-token counts remain unknown, rather than being inferred from character counts. Thinking tokens are part of total output usage, never added again to totals or presented as free compute.
