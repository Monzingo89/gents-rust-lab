This change constrains the decoder using actual data and inspected native types, without supplying task solutions.

`selection_grammar.rs` shares bounded projection enumeration with the existing generic selection grammar. It enumerates every runtime-valid owner-data pointer within the existing six-level/160-byte limits and preserves RFC escaping, empty keys and whole-value pointers. If the complete enumeration exceeds 256 projections or 8192 serialized path-map bytes, it returns no typed grammar. It never uses a partial enumeration to remove choices.

For each inspected component/function pair it creates a positional argument tuple with exact arity. For each parameter it includes every existing owner-data projection accepted by the existing native ABI value validator, grouped by data key. Result-reference identity and projection remain model choices and still receive independent native review. All selected functions remain available, including zero-argument functions. No function, data reference, dependency, actor, output, source body or expected task answer is selected by the host. Matching wire values inside nested data remain available even when they are not whole roots.

Unsupported metadata, duplicate identities, more than 64 function choices or more than 65536 schema bytes retains the original generic decoder. The native ABI, prior-reference, result-type, owner-adoption, source-custody, final approval and runtime receipt checks remain authoritative. Generic fallback does not weaken those admission or authority checks. There is no new package, external service, compiler invocation or paid model/tool call.
