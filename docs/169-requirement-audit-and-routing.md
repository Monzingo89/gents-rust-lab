## Concrete routing failure and change

The existing selector ranked owner-configured full-path latency after profile and memory filtering. A worker with a 2 KiB input ceiling and a faster configured value could beat a larger admitted worker, then fail immediately at the executor's context check. A fixed HTTP regression reproduced that failure with 4,012 bytes of supplied-context JSON: the selected fast worker blocked without inference even though another admitted worker could fit.

The executor and admission path now share `StageInput::for_node`, which constructs the same serialized task/profile/instruction/evidence/dependency/tool envelope. Admission configures the actual registered root nodes and authorized tool list, sizes their initial packets, and filters workers against the existing resolved input-byte ceiling before latency ranking. It keeps evaluated-profile and resident-memory filters. The adaptive default fallback must also fit the initial execution envelope and memory reservation. Analysis-only proposals retain their deferred worker-context behavior and do not dispatch a worker.

The unchanged regression now completes the larger fixture using the larger admitted worker, selects the faster-ranked worker for the small fixture, and rejects an input that fits no worker before any additional dispatch. A separate oversized analysis-only proposal stays non-executing. These tests use explicitly synthetic latency numbers; they establish ranking/feasibility behavior without a model-speed claim.

Later dependencies, tool results, revised plans, native tokenizer context and actual model fit remain checked at dispatch. The initial serialized-byte check does not truncate critical input or guarantee that future stages fit. Routing justification labels its latency input as owner-configured and leaves comparability/optimality unproven.

## TCP fixture failure found during verification

One full Rust run failed before a Cosmos privacy assertion because its mock server read a nonblocking accepted socket before request bytes arrived. A new regression deliberately delays bytes on such a stream and reproduced `WouldBlock`. The fixture reader now explicitly selects blocking mode while retaining its existing two-second read timeout. The accept-loop bound, sensitive-data rejection, row/partition/plan/metrics oracles and production Cosmos verifier are unchanged. All Cosmos fixture tests then passed.

The broader repository run also encountered native Rust assertions while two CPU-heavy test runs overlapped. An affected native component group passed independently under its unchanged limits, and the full repository check then passed when run alone. This is evidence about the observed test orchestration conditions; it does not qualify arbitrary-load reliability or prove a general root cause for every transient failure. Failed runs remain evidence rather than being erased or counted as success. A native result assertion also gained its existing result value as a failure diagnostic; its expectation is unchanged.
