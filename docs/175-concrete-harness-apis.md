# Concrete harness APIs and complexity audit

Inspected November 21, 2026 in the existing dirty `codex/feature/public-research-view` checkout at HEAD `28a8da823231b792030eff5b6172dba29768442f`. This slice follows `AGENTS.md`, `repo-simplify` and `local-evaluate`. It preserves the [verified monorepo boundaries](174-monorepo-architecture.md): root Cargo members remain `crates/harness` and `mcp`, desktop Tauri remains excluded, and frontend/third-party/model directories remain outside Cargo membership.

## Inspection and decisions

The audit read root/member/desktop manifests, the harness HTTP entrypoint and module registration, native MCP library/server/tool registration, launchers, frontend commands and the existing Rust/integration checks. The harness is a binary crate with private root modules, no feature-gated alternative repository implementations and no library/FFI export of the removed traits. Repository-wide searches found no trait-object consumers, generic bounds, alternate implementations, registration entries or configuration keys for these traits. Existing documentation references were updated to the concrete APIs.

| Concern | Concrete evidence | Decision |
| --- | --- | --- |
| Repeated interfaces and speculative storage backends | `SnapshotRepository`, `HandoffRepository`, `ContextArchiveRepository`, `SummaryRepository`, `AnswerRepository` and `WorkflowRepository` each repeated the signatures of one SQLite/file implementation. Every caller constructed that concrete type. | Replace the six traits with inherent methods. Keep the storage modules, types, transactions and caller-owned authorization. |
| Stateless projection layers | `TraceProjector` had only `LocalTraceProjector`, a unit struct used by one HTTP handler and four tests. `EvidenceProjection` had only `Ledger`; no caller abstracted over either trait. | Use `observability::project` and inherent `Ledger::observe`/`handoff` methods. |
| Competing grounded implementations | Harness `task_answers.rs` plus MCP `task_engine/grounded.rs` overlap with `task_workflows.rs` plus `task_engine/workflows.rs` RAG stages. They differ in admission identity, eligibility, subscriber/cancellation/recovery records and configuration. | Retain both. Retiring one requires the lifecycle parity checks in the baseline backlog. |
| Duplicate SDK transaction plumbing | `mcp/src/registry_dotnet.rs` and `registry_angular.rs` repeat receipt construction and bounded MCP-frame checks. Their prepare/compute/finish behavior, native effects, diagnostics and source identities differ. | Retain for this slice. Isolate and independently test the shared envelope contract before extracting a helper; do not merge authorization transactions wholesale. |
| Tiny forwarding modules | Harness `contracts.rs`, `skills.rs` and `security.rs` forward to canonical MCP modules. `scripts/company_tools.py` explicitly lists their source paths; security is also included in a capability revision hash and source-read tests. | Retain the paths and forwarding behavior. They are externally discoverable through governed source tools, not unused files. |
| Useful ports and factories | `CompanyFactory` consumes repository trait objects; coordination engines consume worker/access/journal ports with native and fixture implementations. MCP's tool registry and workflow workers/validators have actual interchangeable implementations. `RuntimePool` selects and owns policy-bound execution capacity. | Retain these boundaries and the public MCP interfaces. |
| Apparent dead code and unused dependencies | `cfg_attr(not(target_os = "macos"), allow(dead_code))` on Angular snapshots/.NET prepared inputs supports platform-gated execution. All direct core dependency names have source/test references, and strict all-target Clippy passes. | No proven unused dependency or removable platform path was found in this inspection. This is not an exhaustive unused-dependency proof. |
| Configuration and fragmentation | Fifteen `config/company.mcp-*.json` variants repeat settings but encode different bounded experiments/model roles. `CONFIG` selects files at runtime. The shared implementations already live in MCP; the harness's large orchestration/task modules implement different authority and recovery paths. | Keep configuration formats, explicit fixtures and module boundaries. No speculative schema, new registry, crate or service is introduced. |
| Misleading documentation | The current baseline described ten fixture checks while `scripts/local_evaluate.py` runs eleven. The context guide said MLX had no tokenizer preflight despite `local_runtime.rs` calling `mlx_prompt::count` for scoped tasks or an explicit context limit. | Correct those descriptions and replace references to the removed traits. Historical trial outcomes remain intact. |

## Two reviewable batches

1. Convert six repository traits to the existing concrete storage methods, merge four adjacent duplicate impl blocks and update imports/call sites. Preserve the alias-resolution doc comment on the concrete method. All 18 operation bodies compare identically with the starting files after removing one obsolete trait import; no SQL, serialization, path validation, lease, budget, epoch or recovery logic changes.
2. Replace the trace trait/unit wrapper with one function and expose the existing two ledger operations directly. The ledger bodies are identical. The trace body differs only by one indentation level, with the unused receiver removed. Its existing tests call the function and retain their assertions.

Measured reduction: eight traits, one unit wrapper and 78 lines across the eight implementation modules, plus obsolete trait imports at callers. Existing storage wrappers that carry a database connection or authenticated scope remain meaningful. There is no intended configuration, persistence, endpoint or runtime behavior change.

Existing regression coverage exercises immutable operator receipts; snapshot scope/hash binding; source-bound handoffs after reopen/revocation/regrant; archive transaction/checkpoint rules; semantic memo custody, leases and permission changes; workflow retry, orphan recovery, checkpoint reuse and live revocation; evidence retention through model switches; and trace privacy/budget/event projection. No fixed evaluator, assertion, resource limit or opt-in real-model test was weakened. This structural refactor reuses that coverage rather than adding tests that merely mirror the new method declarations.

## Validation and limits

- Baseline `cargo fmt --all -- --check` and strict offline locked workspace/all-target Clippy passed. Baseline `cargo test --workspace --offline --locked` passed 712 tests, with 34 opt-in/platform-dependent tests ignored.
- After batch 1, strict harness/all-target Clippy and all 428 harness tests passed, with 24 ignored. Method-body comparison passed for all 18 converted operations.
- After batch 2, strict workspace/all-target Clippy and the full workspace tests passed: the same 712 passed and 34 ignored. Projection-body comparisons also passed. These are fresh results, not historical trial claims.
- `python3 scripts/local_evaluate.py` passed all eleven checks against rebuilt current binaries in 149.60 seconds: build, launcher/probe lifecycle, Rust readiness/shutdown, frontdoor/cache isolation, grounded answers, routing, registered workflows, native stdio, native SSE and screen events. The [private fixture report](../data/local-evaluation/aaf1cd51-ff88-4651-91ef-3dbbe1f81c53/report.json) records zero generative/paid calls and $0 provider fees; hardware/electricity/development cost and real-model task competence remain unknown. The retained [audit evidence](evidence/concrete-harness-apis-2026-11-21.json) binds the report, rebuilt harness and test-log hashes to these measurements.
- No models, paid APIs, downloads, deployments or existing production-service restarts are part of this slice. Real inference/backend model switching, desktop GUI, Linux container behavior and arbitrary external consumers were not requalified. Source fingerprints naturally change when source changes; no old receipt or candidate was promoted automatically.

Existing uncommitted work was preserved. `scripts/experiment_loop.py` and `scripts/local_evaluate.py` changed independently during this turn and were left untouched; those Python edits are outside this slice. The fixture result describes the process invoked here; it does not qualify later independent script edits. All other original paths outside the documented Rust/documentation edits are checked against their starting hashes. No Cargo manifest, lockfile, runtime configuration, public MCP implementation, frontend source or source-read allowlist is intentionally changed by this slice.
