# Owner-adopted dependency compilation

The qualified six-call discovery workflow spent four rejected planning drafts: two incompatible data projections, a graph wire-type error and an early-stage publication criterion. The CEO had already selected the correct result references and the owner had adopted them, yet graph planning independently selected those edges again. This change preserves that existing choice across the phase boundary.

`adopted_dependencies.rs` is a pure adapter. It re-resolves the actual adopted model proposal through the existing discovery validator, checks the selection/data/catalog digest at the adoption revision, requires the actual recorded selection-review message, and compares every invocation, literal and unresolved slot against retained custody and source inputs. Added inputs, edited literals, missing messages, changed digests or changed slots fail closed. Adoption can no longer silently acquire extra calls; changing the selected work requires a new conversation. This grants no execution authority.

For positional templates, the new `adopted_prepared_edges_v1` decoder requires empty argument_sources arrays. The host restores only the exact earlier model-selected and explicitly adopted producer/projection references. The CEO still chooses source actors, staffing, final artifacts, relative paths, pointers, writers, acceptance criteria and definition of done. Existing minimum-capability compilation, private source-bound type checks, runtime receipt/branch checks and final owner approval remain intact. Manual prepared-input planning without selection adoption retains its existing edge-choice protocol. Root-only input plans retain their existing compiler path.

The compiler records a hash of the raw model proposal, the adopted selection digest, a canonical dependency-map digest and source/edge counts. Final native validation independently checks the complete adopted source set and exact references, including at ordinary freeze. The independent workflow verifier derives the same references from the adopted model proposal, checks raw empty-edge declarations and unchanged source actors, compares the compiled graph, and requires matching canonical native audit. It never uses private benchmark role mappings to supply a runtime graph.

Discovery now also checks static result-reference compatibility from inspected metadata using the same type projection rules as source-bound native edge checks. Missing Option/Result branches or vector elements still fail at runtime; static compatibility is not proof of a value's presence. Source/API custody remains separately required. No generated answer, literal, source body, actor, path or dependency is added by a frontier task solver.

Focused native tests cover exact compilation, preserved staffing/publications, changed provenance/literals/slots/declarations, decoder actor choices, empty clarification and static projection parity. The synthetic HTTP custody test now uses a digest-correct explicitly simulated selection message and rejects appended calls after adoption; its unavailable model cannot execute. All 103 MCP-related Node tests pass, including native-audit/hash/edge tampering cases. The prior actual six-call workflow freshly independently reverified PASS. The full gate is running in adopted-dependencies-full-check.log. A fresh sealed-build retest of the unchanged fixture/profile is required before claiming actual planning or token improvements. The broad goal remains active.
