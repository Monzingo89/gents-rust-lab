# Owner-held templates and CEO-selected component edges

The host now accepts partial owned invocation tuples and lets the CEO choose typed producer/consumer edges. The native recipe adapter remains responsible for resolving actual values from current canonical receipts. This extends [the native recipe boundary](102-native-owned-component-recipes.md); a real local-model dependent-task qualification is still required before counting company chaining as a measured capability.

## Owner data and planning

An owned invocation may include `argument_slots`, a list of positional indices whose values must be supplied by earlier native results. Those tuple entries must be explicit empty placeholders. Other arguments are validated immediately using the supported Rust ABI, without compiling or running source. Literal invocations keep their original `input_sha256`; partial tuples instead have `input_template_sha256`. These identities are distinct, and the host refuses both at once or a change to retained literals/slots. Interface selection, source bytes and origin ownership remain immutable private custody. No source body enters a model packet.

The `typed_prepared_edges_v1` adapter uses `native_prepared_graph`. It presents only retained input templates and the owned invocation descriptor. The CEO explicitly selects source actors and references of the form `{field,source,pointer,argument_index,value_pointer}`. `pointer=/output` selects the producer's native return envelope; `value_pointer` selects a typed value inside that return value, or the whole value when empty. The CEO selects every producer, return projection, argument slot, stage and requested output mapping. The decoder supplies no edge, actor, value, source implementation or task answer. The host derives minimum draft tool lists from these choices for owner review.

Fixed prepared IDs are referenced exactly once; arbitrary source/argument copies and extra transformations are not accepted in this mode. All owner-selected slots must be filled exactly once. Cycles, missing producers, unsupported projections, changed literals and future-actor dependencies fail validation. Before a plan becomes ready, the host reads the retained source snapshots privately and uses the same native interface checker to verify producer/consumer wire types. It repeats that check at intake freeze and approved source staging. Native invocation still repeats custody, type, policy and receipt checks at runtime.

## Receipt tracking is separate from file publication

A dependency no longer requires a file the user did not ask for. For an already selected source whose complete return value is needed by another operation, the host creates a deterministic, collision-checked receipt-only binding when no matching requested output projection exists. The identity looks like a safe local label but is never read from or written to the filesystem. This does not create a new computation, select a producer or add a permission. The exact binding is visible in frozen review metadata.

`receipt_only=true` is native/host contract metadata, not a field the CEO may add to a requested artifact. It requires a read-only source and binds its placeholder writer identity to that same source actor. Its success gate requires canonical native source evidence and current dependencies, without file grants, file existence, writes or readbacks. The exact-contract guard refuses file operations through a receipt-only identity. Ordinary published outputs retain their required native write/readback and exact-byte checks. Owner duty separation counts actual publication writers, not internal receipt identities. Source-only operations can therefore complete their native evidence checks with no file-tool grants.

Published outputs remain limited to sixteen; up to sixteen receipt-only bindings have a separate bounded allowance. The combined native binding cap is thirty-two. Raw CEO artifact limits remain sixteen. Named-output discovery, per-stage file obligations and browser review limits distinguish the two classes. Existing jobs without the flag retain their previous behavior, including prior native-submission fingerprints. Models cannot mark a requested file as receipt-only to waive its publication gate.
