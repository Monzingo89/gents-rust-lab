# Local per-agent memory archive checkpoints

`memory_archive.rs` separates the context archive adapter from the company controller. Its `ContextArchiveRepository` interface owns archive and recall storage operations; the company controller retains owner checks, current governance, job lifecycle decisions and audit. The shipped adapter is owned local SQLite using the pinned bundled native library. No Databricks, remote backend, model call, credentials or paid service is involved. Swapping storage does not change those authority rules. A future remote backend would need an explicit transactional outbox/reconciliation design; this interface does not make two systems one atomic transaction.

The adapter requires a caller-owned SQLite transaction. Hot-to-cold transfer, removal from the active FTS index, job-state updates, memory-generation changes, per-agent archive checkpoints and the existing completion audit commit together through the company lifecycle path. SQL transfers avoid copying the entire corpus into host memory; checkpoint hashing reads one record payload at a time. The normal snapshot-before-archive behavior remains.

This atomic boundary is the company database. The separate run journal and filesystem effects retain their existing recovery boundaries. Unix private directory/file modes remain in place; real Windows ACL and cross-platform execution verification are still outstanding.

Completed jobs use ALTC or EVIDENCE_ALTC. An unqualified `candidate_submitted` result now uses PLTC or EVIDENCE_PLTC, with its own `candidate_submitted` checkpoint kind. Previously this state shared the completed tier. Candidate source remains unqualified and unpromoted; finishing it as accepted memory is rejected. Cold storage is excluded from working prompts until explicit owner recall, and recall still rechecks current retrieval grants. An accepted task does not make every intermediate model statement in its history true.

Each checkpoint binds one run, actor and lifecycle to a record count, length-delimited SHA-256 digest over canonical record identity/metadata/body hashes, observed policy revision, frozen contract digest when available, and an update timestamp. It contains no copied model or evidence payload. Missing historical contract/revision data remains null. Repeating a checkpoint with unchanged bytes and bindings is idempotent, including its timestamp; actual record/binding changes update that actor's checkpoint without duplicating it. Other actors' checkpoints remain separate.

Checkpoints are historical storage observations, not qualification, source promotion, recall grants, continuous integrity monitoring or proof of clinical/banking compliance. Historical lifecycle checkpoints may coexist after later owner recall or archival. Old archives are not silently rewritten into fabricated historical receipts. A new owner-requested checkpoint can observe their present state, with its current timestamp.

The owner-authenticated company operation `memory_archive_status` returns these metadata rows and the `owned_local_sqlite` backend label. It does not return memory bodies or bypass agent tools. The source-repair policy protects the new module. The existing agent short-term context, permission epochs, semantic-summary quarantine and evidence retrieval adapters remain distinct.

Recall now places the owner's recall record, cold-to-hot transfer, archive removal, memory-generation changes and recall audit in a single transaction. Previously the recall record could commit before the transfer. A failed transfer now rolls back all these changes. This also prevents a failed recall from advertising a source-generation change to the snapshot worker.

Tests exercise actual SQLite, including an injected checkpoint failure that rolls back job state and records together; repeated/updating per-agent upserts; passive candidate storage through the company lifecycle; rejection of candidate acceptance and other-owner metadata access; and failed recall followed by a successful retry with no lost records. The real HTTP company smoke checks metadata isolation across companies and absence of source payloads. These are storage/governance tests, not simulated claims of local-model task competence. Evidence is under `data/mcp-basement-verification/memory-archive-*.log`.

Strict Clippy and the full repository check passed: 346 default Rust tests, 19 excluded opt-in probes, real HTTP governance/restart checks, Python/Node checks and the UI build. The idle office on port 8788 was gracefully restarted with the tested build and returned health 200.

The accepted v1 scheduling run supplied a real stored corpus for an owner-requested, present-time checkpoint check. Its 45 archived records across three actors matched the read-only native SQLite counts and frozen contract digest. Two repeated owner finish requests returned identical checkpoint metadata, including timestamps. This made zero model/provider calls and did not rerun the task, recall the records or rewrite model text. The receipt is `memory-archive-accepted-run-http-receipt.json`; it records new observations of old records rather than backdating completion checkpoints.

The active weighted-slot v2 task keeps its issued UUID, profile, frozen acceptance and running process. Archive changes are not injected into that benchmark's runtime or task state. The full goal still includes broader memory-use measurement, hardware/model acquisition and training, other modalities and actual domain-specific assurance.
