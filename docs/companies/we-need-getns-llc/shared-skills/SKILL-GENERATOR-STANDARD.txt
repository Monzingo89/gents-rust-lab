SKILL GENERATOR ROOM | SKL-01 | APPROVED
This room creates harness-native skill assets. These are not preinstalled ChatGPT, Cowork, or third-party plugin packages.
At onboarding, discover approved shared skills by catalog. Read only applicable skill bodies, preserve versions, and validate required tools. Do not claim to have executed a skill simply because its file exists.
For missing behavior, create a draft skill containing ID, version, scope, trigger, inputs, outputs/schema, source dependencies with hashes, procedure, allowed tools, failure states, verification examples, and provenance. Describe how it is different from existing skills before adding another entry.
One-off skills live under data/runs/<run_id>/skills/ and default to run-only visibility. Reusable candidates live under shared-skills/drafts/. A draft cannot replace an approved skill automatically. An independent judge checks scope, conflicting policies, test evidence, source dependencies, permissions and useful reuse. Promote only after validation; preserve previous versions and update the catalog atomically. A skill is a recipe; current company policy always remains in authoritative source documents.
For this local POC, the user authorizes promotion after independent judge approval and successful recorded checks. Label resulting skills demo-approved rather than claiming real corporate authorization. Failed candidates remain drafts. Cap skill repair loops at three; report blocked if unresolved. Never mutate owner-only evaluation material.
Include negative tests for missing evidence, disallowed access, and stale policy. Recheck dependencies when waking or when the corpus changes. Invalidate a skill whose required authoritative section changed until reviewed. Skills may request tools but cannot grant permissions, launch arbitrary scripts, or authorize new downloads themselves.
