GENT LIFECYCLE AND MEMORY STANDARD | AGT-01 | APPROVED | version 1.0
1. New arrival: create agent identity, role, run ID, workspace, and capability record. Emit arrived and onboarding_started events. Read the handbook, document catalog, this lifecycle, and shared skill catalog. Discover all departmental records through the catalog; do not grant access to owner-evaluation material.
2. Knowledge onboarding: identify relevant authoritative sections, read them from source, record document ID/version/hash/locator, and produce a compact briefing. The agent can access all company records; it should not blindly place the whole company corpus in an 8K-token prompt. Retrieval and chunking preserve full access without prompt overflow. A summary is a retrieval aid, never a new policy authority.
3. Skill Generator Room: load the approved shared skill catalog. Select relevant skills and verify their compatibility. When a required procedure is missing, create a proposed task-scoped skill, validate it in the run workspace, and submit it for independent judge review. See the skill standard for promotion. Newly generated instructions cannot bypass tool permissions or become company policy.
4. Work: the planner writes a bounded plan and evidence requirements; the worker executes using available tools. Save outputs and source references after each meaningful step. The scheduler, not the model, owns memory and concurrency decisions.
5. Prepare for sleep: stop accepting work, reach a safe checkpoint, record pending tools and side effects, flush structured state and evidence, and write a compact resume summary. Copy reusable source chunks and indexes into a content-addressed quick cache. Do not move or delete canonical originals. Synchronize necessary state to durable storage before releasing inference resources. A sleeping agent retains identity; its model need not remain loaded.
6. Sleep commit: atomically mark the checkpoint complete only after all required files are written. Unload the owned inference runtime if no other scheduled work uses it. An interrupted checkpoint is not resumable until reconciled. Never repeat a completed external action merely because a conversation was reloaded.
7. Wake: load the last committed checkpoint, validate corpus and skill hashes, recheck capabilities, and reconcile pending tool calls. If a source changed, invalidate dependent cached summaries, retrieve the current authoritative material, and replan affected decisions. Reuse valid chunks and approved skills instead of redoing all onboarding. Emit cache hit/miss/stale events with reasons.
8. Completion: preserve the artifacts, verification evidence, skill versions, and run summary. Models may unload; run results must remain inspectable. Cancellation checkpoints preserve completed work without declaring task success.
Suggested paths: data/company/ is canonical; data/cache/company/<corpus_hash>/ holds reusable catalog and retrieved chunks; data/cache/agents/<agent_id>/ holds warm resume material; data/runs/<run_id>/agents/<agent_id>/ holds durable checkpoints and task evidence. These paths are a design contract for integration, not an existing implementation claim.
