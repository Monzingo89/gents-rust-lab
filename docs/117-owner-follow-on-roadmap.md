## Agent construction and governance

Provide an agent builder and factories behind replaceable repositories. Fluent methods configure identity, assigned jobs, local model/transport, tool capabilities, allowed communication peers, memory scopes, budgets and applicable domain control profiles. `Build()` validates a complete immutable candidate configuration; a separate owner-controlled approval step installs authority. Avoid unrelated constructor arguments and framework-specific types in domain contracts.

Factory composition must select a real available architecture and permitted tools from the confirmed task, report missing capabilities, and preserve the existing approval, native source/receipt, cancellation and independent acceptance gates. Transport is an adapter; stdio/SSE selection must not alter access rights. Databricks is not presumed free or necessary; the owned governed SQLite memory adapters remain the local default.

Per-agent short-term memory and completed-task long-term upserts must enforce actor, task, data scope, provenance and current policy. An image actor receives no financial records unless the owner explicitly grants the needed scope. Communication must retain transitive source lineage. Optional controls may be configured by the owner; model output cannot disable authentication, tenancy, confinement or canonical audit.

Domain profiles supply controls, required evidence and explicit gaps. FHIR interoperability is not HIPAA certification; SOC pages are not an attestation. Banking, fintech and health task support requires scoped controls and verification rather than blanket compliance claims.

CEO drift monitoring can pause/cancel affected actors and re-anchor them to the unchanged owner-approved task. Keep earlier outputs/audit evidence; a reminder cannot overwrite canonical history, silently replace acceptance criteria or expand grants.
