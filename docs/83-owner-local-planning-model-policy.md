# Owner-configured local planning models

The preceding hard audio task required manual selection of an installed reasoning model after the coder repeatedly proposed invalid graphs. `planning_models.rs` makes that choice an optional, bounded owner policy. The default remains the configured admin model. No model may install candidates, change thresholds or grant itself tools.

`config/company.mcp-development-adaptive-planner.json` is an explicit evaluation profile. It starts planning with the installed pinned coder, and permits the pinned 27B reasoning candidate after two completed structural failures. Both have an owner-declared 24 GiB host-capacity floor and 16k contexts; the reasoning candidate reserves 2,048 thinking tokens. Mission authorization and independent QA keep the original admin model. This is an experimental role policy, not a general model-quality ranking or automatic production admission.

Selection counts only canonical completed native planning replies under the same policy digest and session: failed fixed-contract validation, normal `stop` finish and a native backend PID. Cutoffs, missing replies, user repair messages, model claims and failures under another policy do not advance the tier. Existing bounded revision/conversation limits still apply. The selector never retries a tool, edits task criteria or supplies expected results.

The owner lists at most four native local GGUF candidates, exact SHA-256 pins, minimum effective host-memory capacity and a 1..3 failure threshold. Host/process capacity comes from the existing OS/cgroup probe. Unknown capacity denies selection. A capacity floor is an owner estimate, not GPU memory or proof that a model fits; the native runtime separately measures slot context and attempts device/GPU/CPU fitting. The selector considers candidates from the requested tier onward, recording why earlier candidates are unavailable. No download, remote provider, credential configuration, training or tool grant is performed.

`model_artifact.rs` independently verifies installed artifact identity without loading or selecting a model. It rejects traversal, symlinks, nonordinary/empty/oversized files and SHA-256 drift. Unix checks also reject extra hard links, foreign owners relative to the trusted repository root, and writable model directories/files. Descriptor/path metadata is checked around streaming the hash. This reduces accidental replacement and other-user modification; a privileged same-user process can still replace a file between inspection and loading. It is not vulnerability certification or proof of actual GPU fit. Backend parser/format checks remain separate.

Policy and candidate/weight identity join the existing company/owner/planning-session inference-cache identity. Changing a policy or pin cannot reuse the previous cached model under the same path. Host observation timestamps do not change identity. Model-selection failures become durable terminal planning checkpoints with `inference_dispatched: false`; they never leave a new orphaned `generating` row. The client stops for host diagnosis rather than repeating configuration failures as model repair prompts.

Canonical planning audits and saved attempts retain the selection proof, pin, capacity observation, requested/selected tier and skipped reasons. The independent Node verifier hashes the exact private frozen profile, reconstructs policy identity, checks the failure thresholds, and matches native model labels, context and reasoning/final budgets. Planning-profile lineage is kept separate from later execution-profile changes. Both data and coding runners use the shared lost-response observer; an HTTP timeout does not replay a planning POST.

Validation includes six selector/cache tests, the existing complete workspace suite (408 passing default Rust tests, 20 opt-in exclusions), strict Clippy/build, frozen-profile/independent-proof tests and a real private HTTP refusal regression. The HTTP test verifies that unavailable candidates create a terminal checkpoint with no model backend, issued job or native tool call, and that caller policy injection is rejected. These infrastructure tests are not model competence evidence.

Run an explicit qualification retest with:

```sh
node scripts/mcp-development-curriculum.mjs --retest audio-routing --approved-workflow --runtime-config config/company.mcp-development-adaptive-planner.json
```

Do not run this concurrently with an active curriculum lease. This policy improves local orchestration; it does not train weights, establish speech understanding or certify regulated-industry use. Provider/tool fees are zero; local inference tokens, compute, power and frontier development remain separate.
