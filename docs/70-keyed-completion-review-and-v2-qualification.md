## Review protocol

`completion_review.rs` now owns the response schema and strict validator. Criteria are presented losslessly under their frozen zero-based string IDs. The native grammar requires a closed checks object with every matching key, such as `checks: {"0": {passed, evidence}, "1": {passed, evidence}}`. Verdicts and passed booleans remain unconstrained semantic choices; neither the schema nor host format repair supplies a favorable judgment.

The validator rejects duplicate raw JSON keys, missing/unexpected IDs, noncanonical IDs, unknown fields, wrong types and empty/oversized evidence. It never renumbers a prior response or fills a missing check. Earlier array responses remain in historical transcripts but do not satisfy this new wire contract. A valid revise/uncertain response or a false check remains nonaccepted. Each review packet currently supports at most 64 criteria; longer acceptance lists still need a batching extension, not dropped criteria or a smaller goal.

Malformed format now produces explicit host protocol diagnostics with a response hash and a statement that no implementation failure was inferred. Up to three reviewer-only attempts use the same frozen request plus those diagnostics. No author proposal or tool execution occurs between them. A valid substantive rejection still goes to the existing bounded repair path. Exhausting format retries records an explicit protocol failure and consumes recovery rather than silently accepting a model's positive summary.

Workspace fingerprints, native source/test/epoch facts and artifact bindings are checked before each review attempt and again after its response. Changed evidence invalidates the review instead of accepting stale judgments. The initial fingerprint is captured before independent content review. These are current-state guards, not an atomic transaction spanning arbitrary filesystem edits and separate stores, or continuous post-admission monitoring.
