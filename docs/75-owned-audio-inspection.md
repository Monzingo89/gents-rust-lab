# Owned audio inspection

`audio_inspect` adds an owned native MCP input adapter for complete local WAV files. It requires a current actor grant, a confined `.wav` path and the approved complete-file lowercase SHA-256. It reads at most 16 MiB and returns source provenance plus measured sample facts. It does not load a model, play audio, transcribe speech, download software or execute a codec/plugin.

The implementation separates three responsibilities: descriptor-relative file access in `workspace.rs`, pure format/statistics code in `audio.rs`, and the thin registered MCP adapter in `functions/audio_inspect.rs`. The same input/result contracts and governance apply through stdio and SSE. No dependency was added. Binary reads are an internal workspace interface for owned adapters, not a new raw-byte agent tool.

The parser accepts a bounded subset: little-endian RIFF/WAVE, one format chunk, one data chunk, integer PCM16 and one or two channels. It checks whole-file declared size, chunk lengths and padding, a 128-chunk budget, rate/alignment consistency, and complete audio frames. Format payloads are limited to 16 bytes or an 18-byte PCM payload with zero extension size. Compressed, float, extensible, RIFX/RF64 and other formats are rejected. Unknown metadata payloads are skipped without being echoed or interpreted. These format decisions follow the primary [RIFF chunk description](https://learn.microsoft.com/en-us/windows/win32/xaudio2/resource-interchange-file-format--riff-) and [WAVEFORMATEX layout](https://learn.microsoft.com/en-us/windows/win32/api/mmreg/ns-mmreg-waveformatex); this does not claim support for every WAV variant.

Results include channels, sample rate, frame count and an exact rational duration `{numerator: frames, denominator: sample_rate}`. Each channel has signed extrema, peak absolute sample, sample sum, zero count, rail count and adjacent nonzero sign-change count. Zero breaks sign-change adjacency. Empty audio has no extrema and zero frames; the mathematical all-zero predicate also holds for an empty sequence. PCM16 signed range and interleaving follow Microsoft's [PCM data description](https://learn.microsoft.com/en-us/windows/win32/multimedia/devices-and-data-types). Counts/sums use bounded integer arithmetic, including the negative full-scale endpoint. Rail hits are measurements, not proof of clipping. The tool does not infer perceived loudness, content, speaker identity, diagnosis or compliance. Measurements and source hashes remain potentially sensitive local data, not anonymization.

Registered tools can now declare `file_input_fields`. Frozen-input protection consumes that metadata instead of naming individual reader tools in policy code. Both table and audio inputs declare their path field, so an output destination cannot overwrite the same frozen input. Descriptor-based file identity additionally denies existing case/Unicode-normalization aliases where the filesystem resolves them to the same file. The alias check reads metadata only and grants no general file-read permission. It covers cooperating governed MCP writes, not arbitrary privileged host filesystem changes or an atomic transaction across the filesystem and SQLite. Complete text and binary reads share the same before/after metadata and size checks; binary bytes never pass through a text decoder.
